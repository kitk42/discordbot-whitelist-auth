# 要件定義書: Discord whitelist 認証 Bot

この要件は `docs/request.md` と `docs/hearing.md`、およびチャットでの追加回答をもとにまとめています。

## 1. 概要

Minecraft Java 版サーバーの whitelist 登録を Discord から申請・承認できるようにする Bot です。管理者がサーバーコンソールで `whitelist add` を手入力する手間をなくすことが目的です。

- 参加者は Discord で Minecraft ID を申請します。
- 管理者は Discord のボタンで承認または拒否します。
- 承認されると、Bot が RCON 経由で `whitelist add` を実行します。

## 2. 前提

| 項目 | 内容 |
|---|---|
| Minecraft サーバー | Vanilla 26.3、Java 版のみ（統合版は対象外） |
| `server.properties` | `online-mode=true`、`white-list=true`、`enforce-whitelist=true`（現在は `false` なので変更が必要） |
| 規模 | Discord サーバー 1つ、利用者は 5人程度 |
| 稼働環境 | Azure VM（Ubuntu 24.04 LTS）。Minecraft サーバーと同じ VM で動かす |
| 言語・ライブラリ | Python と discord.py |
| データ保存 | SQLite |
| Bot が出すメッセージ | 日本語 |

## 3. 利用者と権限

| 利用者 | 判定方法 | できること |
|---|---|---|
| 参加希望者 | Discord サーバーのメンバー全員 | 認証チャンネルで `/whitelist` を使って申請する |
| 管理者 | 設定で指定した管理者ロールを持っている | 管理チャンネルで承認・拒否・削除を行う |

| チャンネル | 見られる人 | 用途 |
|---|---|---|
| 認証チャンネル | メンバー全員 | 申請を受け付ける。結果をメンションで知らせる |
| 管理チャンネル | 管理者だけ（Discord のチャンネル権限で制限する） | 申請への対応と削除コマンドの実行 |

管理者かどうかは、チャンネル権限に加えて、Bot 側でもボタン操作やコマンド実行のたびにロールを確認します。

## 4. 機能要件

### FR-1. 申請: `/whitelist <Minecraft ID>`

1. このコマンドは認証チャンネルでだけ使えます。他のチャンネルで使った場合はエラーを返します。
2. 申請を受け付けるかどうかを、次の順に確認します。1つでも当てはまれば、本人にだけ見えるエラーを返し、管理チャンネルには送りません。

   | 確認すること | エラーにする条件 |
   |---|---|
   | ID の形式 | `^[A-Za-z0-9_]{3,16}$` に当てはまらない |
   | 1人1つの制限 | 申請者が既に承認待ち、または承認済みの申請を持っている |
   | 承認待ちの重複 | 同じ Minecraft ID の申請が、承認待ちまたは承認済みとして既にある（大文字と小文字は区別しない） |
   | 登録済みかどうか | その ID が既に whitelist に登録されている（RCON の `whitelist list` で確認する。RCON に接続できないときは確認を飛ばす） |
   | 申請回数 | 申請者が直近24時間に送った申請が既に5回ある |

3. すべての確認を通過したら、次の処理を行います。
   - 申請を SQLite に「承認待ち」として保存する
   - 管理チャンネルに申請メッセージを送る。メッセージには申請者のメンション、Minecraft ID、申請日時、「承認」「拒否」ボタンを含める
   - 申請者に「受け付けました」と返信する。この返信は本人にだけ見える表示にする

**申請回数の数え方**

- 直近24時間に送った申請の数で数えます（毎日決まった時刻にリセットする方式ではありません）。
- 数えるのは、管理チャンネルまで届いた申請です。承認・拒否・期限切れのどの結果になった申請も含めます。
- 手順2でエラーになった申請は数えません。

### FR-2. 承認

1. 管理者が「承認」ボタンを押すと、RCON で `whitelist add <ID>` を実行します。
2. 実行に成功したら、次の処理を行います。
   - 申請を「承認済み」に更新し、処理した管理者と日時を記録する
   - 管理チャンネルの申請メッセージに結果と処理者を書き加え、ボタンを押せない状態にする
   - 認証チャンネルで申請者にメンションして、承認されたことを知らせる
3. RCON に接続できなかった場合は、管理者にエラーを表示します。申請は承認待ちのまま残し、ボタンをもう一度押せるようにします。
4. サーバーが追加を拒否した場合（ID が存在しないなど）の扱いは、実装の段階で実際のサーバーの応答を確認してから決めます（「7. 実装時に検証する事項」を参照）。

### FR-3. 拒否

1. 管理者が「拒否」ボタンを押すと、拒否理由を入力するフォーム（Modal）が開きます。
2. 送信すると、次の処理を行います。
   - 申請を「拒否済み」に更新し、理由・処理者・日時を記録する
   - 管理チャンネルの申請メッセージを更新し、ボタンを押せない状態にする
   - 認証チャンネルで申請者にメンションして、拒否されたことと理由を知らせる。理由はチャンネルにいる全員に見えますが、了承済みです。
3. 拒否された人は、別の ID でも同じ ID でも、もう一度申請できます。ただし申請回数の制限の範囲内です。

### FR-4. 期限切れ

1. 申請から7日経っても承認待ちのままの申請は、「期限切れ」にします。この確認は定期的に実行します。
2. 期限切れにした申請については、管理チャンネルの申請メッセージを更新してボタンを押せない状態にし、認証チャンネルで申請者にメンションして知らせます。
3. 期限切れになった人は、もう一度申請できます。

### FR-5. 削除: `/unwhitelist <Minecraft ID>`

1. このコマンドは管理チャンネルでだけ使えます。使えるのは管理者ロールを持つ人だけです。
2. RCON で `whitelist remove <ID>` を実行します。`enforce-whitelist=true` にしてあるので、そのプレイヤーが接続中ならその場でキックされます。
3. その ID が Bot 経由の申請と結び付いている場合は、次の処理を行います。
   - 申請を「削除済み」に更新し、処理者と日時を記録する
   - 認証チャンネルで本人にメンションして、削除されたことを知らせる
   - 本人がもう一度申請できるようにする
4. Bot を経由せずに登録された ID（管理者やゲストなど）も削除できます。この場合、本人への通知は行いません。

### FR-6. 処理の履歴

申請・承認・拒否・期限切れ・削除について、次の情報を SQLite に残します。

- 誰が処理したか
- いつ処理したか
- 拒否した場合はその理由

### FR-7. Bot が再起動したあとのボタン

Bot が再起動したあとも、管理チャンネルに残っている承認待ち申請のボタンが動くようにします。具体的には、ボタンの識別子に申請 ID を含め、discord.py の persistent view を使います。

## 5. 申請の状態の移り変わり

```
承認待ち ──承認──> 承認済み ──削除──> 削除済み
   │
   ├──拒否──> 拒否済み
   └──7日経過──> 期限切れ
```

- 申請者がもう一度申請できるのは、その人の申請が「拒否済み」「期限切れ」「削除済み」だけの場合です。
- 「承認待ち」または「承認済み」の申請がある間は、新しく申請できません。

## 6. 非機能要件

| 項目 | 内容 |
|---|---|
| 常時稼働 | systemd のサービスとして動かします。異常終了したときは自動で再起動するよう設定します。 |
| ログ | 標準出力に出し、journald で確認できるようにします。 |
| 秘密情報 | Bot トークン、RCON パスワード、各種 ID は環境変数で渡し、リポジトリには含めません。開発では `.env`、本番ではリポジトリの外に置く `/etc/whitelist-bot/env` から読み込みます。 |
| Minecraft サーバーとの連携 | RCON だけを使います。本番の `/srv/minecraft` は他のユーザーから読めないため、`whitelist.json` などのファイルを直接読みません。 |
| 公開リポジトリ | GitHub で公開します。秘密情報や自宅 IP、Azure の識別子などをコミットしないこと。`server.jar` は Minecraft の利用規約（EULA）により再配布できないため、コミットしません。 |
| RCON | 接続先は `localhost:25575` です。NSG ではこのポートを受信許可していません（既定で拒否される）。外部には公開しません。 |
| 同時操作 | 同じ申請を2人の管理者がほぼ同時に操作した場合、先に処理された方を有効にします。後の操作は「処理済み」として扱います。 |
| Discord の Intent | 特権 Intent（Members や Message Content）は使いません。 |

## 7. 実装時に検証する事項

### 7.1 RCON の応答（Vanilla 26.3 で確認済み、2026-11-22）

| コマンド | 状況 | 応答 |
|---|---|---|
| `whitelist add <ID>` | 成功 | `Added <正式な表記の ID> to the whitelist` |
| | 既に登録済み（大文字・小文字が違っても同じ扱い） | `Player is already whitelisted` |
| | ID が存在しない | `That player does not exist` |
| `whitelist remove <ID>` | 成功 | `Removed <ID> from the whitelist` |
| | 登録されていない | `Player is not whitelisted` |
| | ID が存在しない | `That player does not exist` |
| `whitelist list` | 0人 | `There are no whitelisted players` |
| | 1人以上 | `There are N whitelisted player(s): name1, name2` |

- `whitelist add notch` のように小文字で指定しても、サーバーが Mojang から正式な表記（`Notch`）を取得して登録します。
- Vanilla の RCON は、複数のパケットをまとめて送ると接続を切ります。クライアント側で 1 パケットずつ送るように実装しました（`src/whitelist_bot/rcon.py`）。
- RCON は `0.0.0.0:25575` で待ち受けます。どこからの接続を受け付けるかをサーバー側の設定では絞れないため、外部から守るのは NSG の役割になります。

### 7.2 検証結果をもとに決めた事項

1. **承認したときに `That player does not exist` が返った場合**: 自動で「拒否済み」にします。理由は「Minecraft ID が存在しません」とし、申請者にメンションで知らせます。
2. **承認したときに `Player is already whitelisted` が返った場合**: 「承認済み」として扱います。
3. **申請時に RCON に接続できない場合**: whitelist に登録済みかどうかの確認を飛ばして、管理チャンネルに送ります。既に登録済みだった場合は、承認したときに 2 の応答で分かります。

## 8. 開発と運用の方針

詳しい手順は環境構築の段階でまとめます。ここでは方針だけを記載します。

- **開発環境**: WSL で開発します。動作確認には、テスト用の Discord サーバーと Bot、WSL 上のテスト用 Minecraft サーバー（26.3）を使います。
- **`server.jar`**: ユーザーが手元のファイルを作業ディレクトリに置きます。Claude はダウンロードしません。
- **デプロイ**: GitHub に push し、VM 上で `git pull` してから systemd のサービスを再起動します。
- **VM 側の準備**:
  - `server.properties` で RCON を有効にし、`enforce-whitelist=true` に変更してから、サーバーを再起動します。
  - `free -h` で空きメモリを確認します。

## 9. 最初のバージョンの対象外

- Mojang API を使った ID の実在確認
- 統合版（Bedrock）への対応
- Discord サーバーを抜けた人の whitelist を自動で削除する機能
- 申請状況や登録済み ID の一覧を表示するコマンド
- Discord のロール付与
- Discord アカウントとの紐付けがない whitelist 登録を禁止する機能。管理者やゲストのような例外を手動で登録できるようにするためです。
- GitHub Actions による自動デプロイ（今後の検討事項）。実現するには SSH のポート 22 を GitHub のサーバーにも開く必要があり、今の NSG の方針と合わないためです。
